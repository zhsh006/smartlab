# SmartLab V3 现状审评报告

审评日期：2026-10-14。对象：本机运行的 `https://localhost:3159/`，源码位于 `C:\项目汇总\AGI项目\smartlab\LabSmart`。交付形式：文字报告和真实页面截图。

**结论：当前版本不能通过 V3 MVP 验收。** 已有真实记录、上传、待关联和周期汇报基础，值得保留；但科研主链尚未闭环，并且已复现同名原始文件覆盖。按验收清单，任一 P0 未解决即不能通过。主要问题需要调整流程和数据关系，单纯换颜色、隐藏按钮不足以解决。

本次没有修改业务源码、权限或部署，没有访问或修改实验室生产服务器。为了核对实际行为，仅在本机演示实例新增两个明确标注的审评实验和一个人工文件数据包，详见文末。

## 1. 依据与版本边界

本次以 [SMARTLAB_V3_CONTEXT.md](C:/项目汇总/AGI项目/smartlab/SMARTLAB_V3_CONTEXT.md) 和 [SMARTLAB_V3_ACCEPTANCE.md](C:/项目汇总/AGI项目/smartlab/SMARTLAB_V3_ACCEPTANCE.md) 为当前产品与验收依据；V1.0 开发规格作为工程背景。

这两份 V3 文档是聊天有效结论的整理，不是逐字聊天记录。它们明确要求：当前实验是工作台主体；平时少量记录；Agent 自动收集、人确认归属；RAW 与 Figure 分开；集中做周/双周汇报；导师反馈进入下一轮计划。

此前的 `SmartLab_V1范围收缩对照表.md` 标注为“建议稿，待确认”。其中把 Agent、Figure 等后移的建议不能覆盖 V3 已确定的核心方向。“减轻学生负担”应通过带入已知信息、后台收集和减少重复确认实现，不能把保存来源、整理 Figure、导师查看这些核心能力一并削掉。

当前实物是 eLabFTW 的 PHP/Twig/TypeScript/MySQL 定制系统，核心数据库 schema 206，运行于本机 Docker。容器名为 `smartlab-v4-elabftw`、`smartlab-v4-elabftw-mysql`。容器名中的 v4 不能当作已通过验收的产品版本号。

相对原始源码压缩包，原有 DashboardController、SmartlabBenchRecords、SmartlabDashboard、dashboard.html、head.html 已有变化，另新增快速记录、Agent/数据中心、周期汇报等模块。因此，当前审评对象已经包含新的功能改动，不能沿用此前“只修部署、业务源码未改”的判断。

证据分为三类：**实际复现**（浏览器或人工文件测试）、**源码确认**（当前服务端实现明确缺少或允许某行为）、**未完整验证**（需要另建角色/项目、重启或实机测试）。未完整验证不记为通过。

## 3. A：严重偏差与修复判据

### P0-01 原始同名文件覆盖——实际复现

**路由/证据：** `smartlab-agent.php`、截图⑤、[人工文件校验结果](C:/项目汇总/AGI项目/smartlab/LabSmart/docs/ux-audit-20261014/agent-collision-evidence.json)。

将两个不同目录中的 `same-name.csv` 同时发送到已有本机 Agent 接口：输入内容及 SHA-256 不同，接口返回成功并声称接收两份；数据库有两条文件元数据，但唯一存储路径只有一个；存储字节与第二份一致，与第一份不一致。采集侧两份源文件没有删除。这证明服务器第一份 RAW 已被覆盖，清单上的“2 个文件”不能代表两份完好原件。

**根因：** [服务端文件存储](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/web/smartlab-agent.php:95) 使用包目录加 basename；[Agent 多文件打包](C:/项目汇总/AGI项目/smartlab/LabSmart/tools/agent/smartlab-agent.py:130) 同样只传 basename，丢弃相对目录。仪器多个 Run 输出同名结果时很容易触发。

**需求/风险：** 验收 2.2 要求同名不覆盖且下载 SHA-256 与采集原件一致。当前行为会造成原始数据丢失和证据链不可信。

**修复判据：** 每个 RAW 使用独立存储标识，保留原文件名和相对路径；提交源端大小/hash/mtime 清单；服务端完整校验后应答；失败不能被标为成功。此问题应在进入真实仪器采集前解决，不能靠要求学生手动改所有文件名规避。

### P0-02 设备接入凭据权限越界——界面与源码确认

**路由/截图关联：** `smartlab-data.php`，截图⑤是同页安全区域；含完整令牌的设备表区域不写入报告或截图，避免再次泄露凭据。

普通学生账号可看到当前团队设备的完整接入令牌，并有生成令牌入口。设备表已有学生创建的令牌。本次没有新生成或修改任何令牌。

**根因：** [readAgents](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/src/Models/SmartlabDataCenter.php:204) 返回团队设备全字段；[创建动作](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/src/Controllers/SmartlabDataController.php:53) 和 [createAgent](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/src/Models/SmartlabDataCenter.php:214) 未限制为管理员。

**需求/风险：** 设备接入由管理员配置；普通学生获取团队接入凭据后可以冒充采集设备提交数据。权限问题必须由服务端处理，隐藏菜单不够。

**修复判据：** 设备接入配置限定授权管理员；普通科研用户不接收原始令牌；令牌有合理的显示、存储和撤销机制；设备身份以凭据绑定的设备为准。

### P0-03 RAW/LINK 及项目隔离验收缺口——源码确认，未做完整越权实测

**路由/截图：** `smartlab-data.php`、截图⑤/⑪。

包模型只有一个 `experiment_id`，已处理数据包不能再改关联；没有独立 LINK 更正历史或一个 Run 多实验关系，不能通过验收 2.1。关联时会调用实验的写权限校验，这一点正确，应保留；但包列表只按 team 过滤，并连接显示实验标题，没有按项目成员授权过滤。

**源码：** [包列表](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/src/Models/SmartlabDataCenter.php:76)、[关联及实验写权限校验](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/src/Models/SmartlabDataCenter.php:140)。

**风险/边界：** 当前只有一个演示项目，尚未实际创建两个项目和学生 A/B 验证全部下载、搜索、缩略图及导出越权；不能声称已复现所有跨项目泄漏。但实现缺少 V3 要求的项目级读取条件，也不能据现有一项目演示判定权限通过。

### P0-04 失败导入仍显示归档成功——源码确认

**路由/截图：** `smartlab-data.php` 的“确认归档”，截图⑤。

文件不存在或导入异常时记录为 missing/failed 后继续，最终仍将包整体置为 linked；即使导入计数为 0，控制器也显示“数据包已归档到实验记录”。没有在关联前校验所有文件是否与接收时 hash 一致。

**源码：** [逐文件导入和包状态更新](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/src/Models/SmartlabDataCenter.php:158)、[0 文件仍成功提示](C:/项目汇总/AGI项目/smartlab/LabSmart/apps/elabftw/src/Controllers/SmartlabDataController.php:48)。

**风险：** 学生以为原件已入档，实际材料可能不完整；部分失败后没有明确恢复路径。该结论来自当前分支源码，本次没有人为破坏已有服务器文件来触发失败。

**修复判据：** 展示可核对的逐文件完整状态，归属确认和原件完整状态分开，失败可重试；缺原件或校验失败不能用“归档成功”结束流程。

## 6. D：推荐学生与导师主流程

```mermaid
flowchart LR
    P[课题计划草稿] --> C[学生确认计划与方案版本]
    C --> E[当前实验：稳定编号与阶段]
    E --> R[跨天轻记录：变化、异常、照片]
    R --> A[Agent 收集并校验 RAW]
    A --> I[待关联数据]
    I --> L[学生确认归属，可稍后处理]
    L --> X[熟悉的外部软件分析]
    X --> F[Figure 版本及来源]
    F --> W[周或双周汇报：固定版本]
    W --> T[导师查看与讨论]
    T --> P
```

学生只在三个必要位置作主要确认：开始时确认计划/方案，实际记录发生变化或异常时补充，收到数据时确认归属。周期汇报集中整理已有 Figure。系统在后台自动收拢编号、保存时间、来源及版本，不把这些变成学生反复填写的表。

导师工作台优先展示待讨论的周期汇报、关键 Figure、实验异常和下一计划；深入时才打开完整实验及原件。教师阅读效率来自统一摘要与真实来源，不能以要求学生每一步审批来换取。
