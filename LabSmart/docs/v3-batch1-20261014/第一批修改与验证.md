## 学生实际看到的变化

- 首页改为“实验工作台”，主体是当前实验卡，显示真实批次编号、类型、样本/分组、最近记录、草稿/确认状态和下一步。
- 有现场记录的实验优先展示；周任务和提醒收在下方，保留已有任务数据。
- “继续实验”恢复到最近记录的阶段；已确认阶段可以继续下一阶段。草稿明确标注，不当作已经执行。
- 新建实验直接进入同一套快速记录页。原有背景、样本和方案信息保留，但默认收起，避免每次重复阅读。
- 手机菜单默认收起；常用记录输入与保存按钮字号/触控尺寸增大。没有新增逐步审批或强制报告。
- 数据页保留一次人工归属确认；有问题的原件不能被点击归档。普通学生不再收到设备接入配置和令牌。

## 原件与权限的修改

原文件名与存储标识分开，同名文件分别保存。新版 Agent 在发送前计算 SHA-256、大小及源文件时间，服务端逐个比对后接收；传输中内容改变会失败并重试。重复发送同一清单复用接收回执，不重复建包。源文件保持原样。

确认归属前再次核对服务器 RAW；入实验附件后再次读取存储字节核验，并保存完整 SHA-256、标为不可覆盖。任何缺失、哈希不符或导入失败都不能显示完整成功，部分导入留在待处理状态，可继续原实验的导入，避免重复建附件。

设备配置由服务端限制为管理员。GET 列表不返回令牌；新令牌以哈希存储，只在创建成功时显示一次。创建设备时明确选择数据接收人，待关联包按接收人读取，已关联包按实验项目成员或无项目的本人范围读取。系统管理员身份不能绕过这个数据包列表的项目条件。

既有设备令牌保留，但仪器端需换用更新后的 [smartlab-agent.py](C:/项目汇总/AGI项目/smartlab/LabSmart/tools/agent/smartlab-agent.py)。旧版 Agent 缺少源文件清单时会明确拒绝接收；不要继续使用旧脚本。数据包来源设备由凭据绑定，不接受客户端任意改写设备名称。

新增表通过 [002_v3_ingest_safety.sql](C:/项目汇总/AGI项目/smartlab/LabSmart/database/elabftw/002_v3_ingest_safety.sql) 显式、幂等迁移；启动脚本会执行同一迁移。迁移需要既有本地 V3 表，不是空库安装程序。不推测无法确定的历史待关联包归属，不改变旧 RAW 或已提交汇报。
