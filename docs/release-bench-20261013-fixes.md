# 实验现场记录版：页面验收与修复

日期：2026-10-13。线上发布仍使用 `bench-20261012` 名称，本次为补充修复。源码位于文档文件夹内的 LabSmart 项目，未向 GitHub 推送。

## 已修复

1. 命令行导出和验收以 root 运行，创建了网页进程无法维护的私有 Twig 缓存，导致登录页报错。缓存属主已恢复为 nginx，验收脚本在属主不一致时提前拒绝运行；后续 PHP 维护使用 `docker exec --user nginx`。
2. 通用文件上传的后备控件成功后直接整页刷新，丢失了当前步骤的关联目标。上传完成事件现在允许步骤记录先刷新附件列表、保存关联及草稿，再返回该步骤。
3. 已关联课题返回 `project_id`，新送审界面及权限检查使用 `id`，导致选项有文字却没有有效值。关联课题现在同时返回两个兼容字段，保留旧功能并修复送审。
4. 送审前会等待尚未保存的草稿；失败时在原页面显示服务器给出的缺项，保留课题、用途与意见，避免重新填写。
5. 空正文的 null/空字符串及附件字段顺序差异被误判为“提交后更新”。比较已规范化，未修改的提交不再误报；实际结论修改仍被识别。

## 实际页面验收

使用独立系统验收记录，未进行真实科研操作：

- 从 WB 模板创建记录，选择样本，填写并确认四个关键步骤。
- 导入两行五列 CSV；原始值 0 和 1.25 在自动保存、刷新、导师只读视图中保持一致。
- 在具体步骤上传操作单 PNG，上传完成后自动关联该步骤，未错误关联到结果；原始 CSV 单独关联结果。
- 从本条实验导出操作单，将第一页上传回同一条记录；纸质转录要求原始证据、实际操作时间与说明，网页正确区分操作时间与系统录入时间。
- 改动已确认步骤后直接送审，会先保存草稿并阻止正式送审，明确列出需重新确认的步骤，输入保持不变；中途指导请求可提交。
- 确认关键记录后完成正式送审，导师个人待办显示一项正式审核。
- 学生随后修改当前结论，导师打开提交版本仍看到原结论和原始数值，结构化记录没有可编辑表单，并提示提交后有一处更新。
- 导师退回时空意见会被阻止；填写意见后成功保存，导师待办归零，学生看到“待修改 / 退回修改”及该意见。
- 桌面与窄屏布局检查；请求 390 像素窗口时，页面内容宽度 375 像素（含滚动条），无整页横向溢出。结果表在自身容器内滚动。

复用事务验收新增了已关联课题编号一致性和未修改提交无误报的断言；以 nginx 运行通过，回滚后无验收实验残留。JavaScript 语法、PHP 语法及部署摘要检查通过。
