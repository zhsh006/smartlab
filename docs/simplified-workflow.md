# 师生工作流简化方案

## 改版目标

把产品的主要入口收敛为“实验记录本 + 导师待办”。沿用 eLabFTW 的用户、权限、附件、修订、签名、实验记录和数据库能力，改进导航与日常操作，不迁移或重建科研数据。

## 三个核心页面

### 实验列表

- 主导航仅保留课题、实验记录、待办，个人菜单保留资料与管理入口。
- 学生默认查看自己的实验；导师查看团队实验与分配给自己的待审核任务。
- 首屏优先显示继续记录、待补充、待审核等可操作事项。
- 搜索和课题筛选直接作用于实验列表，突出“新建实验”。
- 不把模型状态、算法阈值和技术模块作为日常首页内容。

### 实验详情

- 同一页面按目的、过程、原始附件、结果、导师意见组织内容。
- 新建先填写标题、日期和课题；实验类型及详细参数通过模板展开。
- 附件直接绑定当前实验，保留原图、文件名、上传时间和修订记录。
- 统一显示准备、记录、待补充、待审核、已完成等业务状态。
- 辅助检查显示具体问题及对应补充入口，例如“缺少原始条带图”。
- 技术模块作为可展开的辅助工具，不要求学生依次访问独立算法页面。
- 原始记录、人工确认值和推理内容明确区分；缺测不显示正常，无法分析不显示低风险。

### 导师审核

- 默认仅显示当前导师的待办，历史审核单独查看。
- 每项审核对应唯一任务与提交版本，避免同一实验重复卡片。
- 集中展示原始附件、结构化结果、缺失项、本次修改和历史反馈。
- 保留通过、退回补充、拒绝，提供清晰的意见输入区。
- 不使用重复的 HTML 标识；所有输入和图标按钮有可访问名称。

## 视觉方向

白色主界面、低对比灰色分隔和少量蓝色操作强调，保留既有品牌与图标资源。减少渐变、大面积数字卡片、重复标题与技术术语。正文优先可读，宽表有独立滚动区域，窄窗口按任务内容重新排列。

## 必要验收

1. 学生能在列表找到或新建记录，从同一实验页面添加附件、确认结果和提交审核。
2. 导师能从自己的待办进入同一记录查看证据并反馈，退回意见可被学生看到。
3. 一个实验只显示一个明确的当前阶段，跨页面状态一致。
4. 无附件、缺测数值和服务故障均有明确状态，不显示虚假的正常或在线。
5. 已有实验、权限、原始附件和修订历史可继续访问。
6. 当前在线版的完整源码取得后再执行功能修改与部署验收；旧审查包不作为当前部署版本的依据。
